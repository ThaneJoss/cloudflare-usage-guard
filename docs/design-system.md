# 控制台设计系统

## 设计目标

Cloudflare Usage Guard 不是营销页，也不是带装饰图表的账单复刻。界面遵循四条约束：

1. 先回答“现在最危险的是什么”，再展开全部产品。
2. 只可视化 API 真正提供的数据，不从单个快照推导虚假趋势。
3. 将近实时估算、请求时快照、下限数据和官方日级账单值明确分开。
4. 数据源局部失败时保留其余可操作信息，并让过期状态可见。

## 信息架构

```text
控制台
├── 全局状态栏：LIVE / DEMO / STALE、生成时间、刷新
├── 账户态势：最高利用率、风险结论、摘要
├── 当前压力信号：前三项真实利用率
├── 免费额度雷达：产品筛选、指标和重置时间
├── 可计费用量：账期累计与成本驱动因素
└── 数据覆盖：采集器健康、刷新节奏和近实时覆盖缺口
```

首屏没有轮播、自动播放或假趋势图。风险环代表所有可比较指标中的最高利用率，压力信号
按同一字段排序，因此视觉优先级可以从数据契约直接复算。

账单区不复刻 Cloudflare 已提供的日成本图、历史账期、筛选器和预算提醒。它只展示账户
累计与按产品族聚合的成本驱动因素，并把完整分析交还官方账单中心。

## 视觉语言

沿用 webapps 的浅色视觉：浅灰背景、白色面板、蓝色主操作和轻边框。风险仍使用
绿、黄、红并配合文字表达，与主操作颜色分离。颜色、间距、圆角、阴影和字体集中在
`src/styles/tokens.css`。

- `--accent` / `--accent-strong`：蓝色主行动、品牌与链接。
- `--info`：辅助信息；`--green`：在线与健康状态。
- `--amber` / `--red`：关注、临界、超限与刷新失败。
- `--muted` / `--faint`：次级元数据；仍需满足正文对比度要求。
- 标题使用紧凑无衬线字族，代码和遥测标签使用等宽字族。
- 可读正文不小于 `12px`，关键操作、说明和数据标签优先使用 `13–16px`；仅装饰性
  遥测标签允许使用 `11px`。
- 正文与背景至少满足 WCAG AA `4.5:1` 对比度；大号文字和必要的非文本控件状态至少
  满足 `3:1`。装饰边框不承载状态语义，状态也不能只靠颜色区分。

动态宽度只表达真实的利用率或风险压力。去除装饰网格、光晕与风险环外侧虚线，
保留简洁加载指示和真实利用率环。首屏标题为 30–48px，区块间距为 48–64px。

## 状态模型

| 状态 | 界面行为 |
| --- | --- |
| 首次加载 | 直接读取构建时固定的 API Origin，显示独立加载页 |
| 成功 | 显示 `LIVE` 或 `DEMO` 与快照生成时间；数据源另标刷新节奏与数据截止时间 |
| 后台刷新 | 保留当前内容，按钮和主内容标记忙碌 |
| 刷新失败 | 保留最后成功快照，标记 `STALE` 并提供重试 |
| 首次加载失败 | 显示恢复页与重试，不要求用户再次登录或填写端点 |
| Access / 网络错误 | 在恢复页提供 API 状态检查入口 |
| API / 契约错误 | 只给对应诊断，不误导用户进入 Access |
| 组件崩溃 | Error Boundary 提供恢复与安全演示入口 |

请求使用序号屏障和 AbortController。较早响应不会覆盖较新的刷新，25 秒超时会归类为
独立错误。浏览器不持久化 API Origin、令牌或响应内容。

## 响应式规则

- 宽屏：风险态势、摘要和信号队列形成紧凑的控制台网格。
- 中屏：摘要与产品卡收敛为两列，保持风险优先顺序。
- 窄屏：所有核心状态保留，账单行转换为带 `data-label` 的卡片，不隐藏
  `LIVE` / `DEMO` / `STALE`；导航换行至第二行并保持可访问。
- 交互目标保持至少 44 CSS px；筛选区域允许横向滚动，不缩成不可读的小字。
- 用户选择更高系统对比度时，界面进一步增强文字、面板和边界对比。
- 打印样式去除装饰和交互控件，保留数据、时间与口径说明。

## 无障碍约束

- 页面提供跳到主要内容链接。
- 筛选按钮暴露 `aria-pressed`。
- 进度条包含名称、最小值、最大值、当前值和文本值。
- 刷新、错误和空状态使用适当的 live region，不依赖颜色传达结果。
- 表格包含 caption 和列标题；移动端转换后仍保留同一 DOM 语义。
- 图标链接提供产品名称；纯装饰图标从可访问树隐藏。
- 支持 `prefers-reduced-motion`，关闭加载旋转和过渡动画。
- 焦点样式使用可见外框，不移除浏览器键盘导航能力。

## 性能约束

当前界面不引入图表运行时、CSS-in-JS 或远程字体。风险环和进度条由 CSS 原生绘制，
图标按 ESM 引入。生产构建：

- 禁止 source map。
- JS gzip 上限 90 KiB。
- CSS gzip 上限 12 KiB。
- hash 静态资源使用一年不可变缓存。
- HTML 和 API 响应不做不可变缓存。

`scripts/check-bundle.mjs` 在 CI 中强制执行预算，依赖升级导致体积回归时会直接失败。

## 组件与文件边界

- `src/App.tsx`：只负责状态路由与页面组合。
- `src/hooks/useUsageData.ts`：首次加载、刷新、竞态和超时。
- `shared/usage-schema.ts`：前端与 Worker 共用的完整运行时契约。
- `src/lib/usage.ts`：筛选、排序和格式化。
- `src/components/`：按页面区块拆分的纯展示组件。
- `src/styles/`：令牌、基础、壳层、控制台和响应式样式。
- `shared/quota-catalog.ts`：前后端共用的额度与产品元数据。
- `worker/src/`：Access 验证、Cloudflare API 客户端、两级缓存和聚合器。

新增产品时必须先补共享目录与来源口径，再接入 Worker 采集器和 UI；不得仅在前端添加
静态进度卡。
